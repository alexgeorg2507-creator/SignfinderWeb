## §1. P0 — критический баг: share-ссылка ведёт на прод независимо от окружения

### Репро
Владелец подписал сделку на `signfinder-cab-test.web.app`, нажал
«Скопировать ссылку», открыл в другом браузере — получил ссылку на
`signfinder.app/sign/{token}` (прод), а не на test. Прод ещё не
задеплоен (`TASK_deal_cycle_E7.md`) — 404. **Пока не починено, весь
Deal Cycle нельзя протестировать со стороны контрагента на test вообще.**

### Причина — найдена, не гипотеза

`app/models/deal.py`, модуль-level константа:

```python
_SHARE_URL_BASE = "https://signfinder.app/sign"
```

Используется в `Deal.from_row()` — единственном месте где строится
`share_url`, дальше он просто передаётся как есть в `create_deal`,
`get_deal`, `mark_shared` (все три возвращают `Deal.from_row(...)`, дублирования
логики нет — это единственная точка правки). Фронтенд, судя по всему,
просто копирует `share_url` из ответа API как есть — значит фронт трогать
не нужно, чинится в одном файле бэкенда.

### Фикс

Cloud Run **уже** получает `ENVIRONMENT=test`/`ENVIRONMENT=prod` как
env var (`cloudbuild-test.yaml`/`cloudbuild-prod.yaml`, `--set-env-vars`)
— ничего заводить не нужно, просто читать то что уже есть:

```python
import os

_WEB_BASE_URLS = {
    "test": "https://signfinder-cab-test.web.app",
    "prod": "https://signfinder.app",
}
_SHARE_URL_BASE = _WEB_BASE_URLS.get(os.environ.get("ENVIRONMENT", "prod"), "https://signfinder.app") + "/sign"
```

### Проверка (обязательно живая, не юнит-тест на этом)

На test: создать сделку → «Скопировать ссылку» → убедиться что ссылка
начинается с `https://signfinder-cab-test.web.app/sign/` → открыть в
другом браузере → страница реально открывается (не 404).

Бампнуть `signfinder-api/pyproject.toml`.

## §3. «Мои сделки» — дешёвая часть (в этом PR)

### 3.1 Имя файла + дата — уже должны быть на бэкенде

`deals` таблица хранит `original_pdf_path` (из которого можно вытащить
исходное имя файла, если оно там сохранено — проверить) и `created_at`
(уже есть). Если имя файла нигде не сохранено отдельным полем — значит
`original_pdf_path` его не содержит (сейчас путь генерируется как
`deals/{deal_id}/original.pdf`, оригинальное имя теряется). В этом
случае — добавить `original_filename TEXT` в `DealCreate`/миграцию,
прокинуть с фронта (там оно точно есть, из `<input type=file>`).
Показать в `DealListItem` (сейчас там нет ни файла, ни даты в UI —
проверить, может дата уже приходит но не рисуется).

### 3.2 Крестик — скрыть, не удалить

**Важно, не хардить настоящий DELETE.** У сделки есть юридический
след (E7 — IP/UA обеих сторон в финальном PDF, это доказательство
подписания). Хард-delete по прихоти инициатора стирает это без
причины — сделка должна дожить свои 7 дней ретенции (`ADR-009`)
независимо от того, хочет ли инициатор её видеть в списке.

Новая колонка `hidden_by_initiator BOOLEAN NOT NULL DEFAULT false` +
миграция. Новый эндпоинт:

```
POST /v1/deals/{deal_id}/hide
```

Тот же паттерн что `mark-shared` — атомарный UPDATE, 404 если чужая
сделка. `list_deals` по умолчанию фильтрует `WHERE hidden_by_initiator = false`.
Крестик в UI дёргает этот эндпоинт, не показывает подтверждение
«удалить навсегда» — потому что это не то что происходит.

**Прежде чем писать — прочитай `job_processors.py`/`job_storage.py`/
`tasks.py`.** В проекте уже есть механизм фоновых задач — экстракция
должна идти через него как fire-and-forget после `create_deal`, не
блокировать создание сделки синхронным LLM-вызовом.

Направление (не жёсткая спека, подгони под то что реально есть в
job-системе):
- Новые колонки `deals`: `counterparty_name TEXT`, `contract_date DATE`,
  `summary TEXT` — все nullable, старые сделки просто не имеют
- Один LLM-вызов через `LLMClient.complete_structured()` (универсальный
  промпт, как договорились в `MULTILLM_PROMPTS_DECISION.md` — не плодить
  провайдер-специфичные тексты) на текст уже распарсенного PDF
  (`/v1/me/analyze` его уже парсил — не парсить второй раз)
- Заполняется асинхронно после создания, список может первое время
  показывать «обрабатывается…» пока поле пустое

Если по факту не укладывается по времени в этот батч — не тащи
насильно, вынеси в `TASK_fix16.md` отдельно и скажи явно в отчёте.
