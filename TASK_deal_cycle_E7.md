## §1. Backend (`signfinder-api`)

### 1.1 Инициатор не попадает в юр. блок с IP/UA — критерий готовности §9 п.8 не выполняется

`app/routers/deals_public.py::_append_legal_block` уже реализована (E2), но
несёт свой собственный `TODO(E7)`:

> инициатора IP/UA нет в блоке — `POST /v1/deals` (E1) их не захватывал,
> т.к. запрос создания сделки — не тот запрос, что породил подписанный PDF.

Спека §7 (шаблон юр. блока) и §9 критерий 8 требуют IP/UA **обеих** сторон.
Сейчас есть только у контрагента (захватывается в `sign_public_deal`).

**Решение — без миграции:** добавить ip/ua в уже существующее событие
`created` в `audit_log` (JSONB, менять схему не нужно).

`app/routers/deals.py::create_deal`:
- добавить параметр `request: Request` в сигнатуру
- переиспользовать `get_client_ip` и паттерн обрезки UA `[:300]` —
  та же логика уже есть в `app/rate_limit.py` / `deals_public.py`,
  не изобретать заново
- расширить событие:
  ```python
  audit_log = [{
      "event": "created", "at": now.isoformat(), "actor": "initiator",
      "ip": get_client_ip(request), "ua": request.headers.get("user-agent", "")[:300],
  }]
  ```

`app/routers/deals_public.py::_append_legal_block`:
- убрать неиспользуемые сейчас параметры, заменить чтением из
  `deal["audit_log"]` — найти первое событие с `event == "created"`,
  взять `ip`/`ua` оттуда (fallback на `"—"` если вдруг отсутствует —
  сделки, созданные до этого фикса, не имеют этих полей, не должны
  падать с исключением)
- добавить строку в текст по образцу того что уже есть у контрагента:
  ```
  Инициатор: {email}
    Подписано: {timestamp UTC}, IP {ip}, UA {ua_shortened}
  ```
  (сейчас там только `Подписано: {timestamp}` без IP/UA — привести к
  формату спеки §7, симметрично блоку контрагента)

**Не в скоупе:** ретроактивный бэкфилл ip/ua для уже существующих на test
сделок, созданных до фикса — юр. блок для них останется без IP
инициатора, это нормально (сделки тестовые).

## §2. Frontend (`SignfinderLand`)

### 2.1 Новая страница `/pep-agreement`

`firebase.json` — `cleanUrls: false`, значит нужен явный rewrite (иначе
404, ссылка из футера уже смотрит на `/pep-agreement`):

```json
{ "source": "/pep-agreement", "destination": "/pep-agreement.html" }
```

Добавить в массив `rewrites`, до общих `/en`/`/ru` записей — порядок в
Firebase Hosting matter, но `/pep-agreement` не пересекается ни с чем
существующим, можно в конец.

Создать `SignfinderLand/pep-agreement.html` — статическая страница, стиль
переиспользовать из `sign/index.html` (тот же `:root` набор CSS-переменных,
тот же топбар). Содержание:
- Тот же текст согласия, что уже в чекбоксе `sign/index.html` (не
  придумывать заново — копировать один в один, расхождение между чекбоксом
  и «полным текстом соглашения» — плохо для юридической цели документа)
- Короткое пояснение простым языком: что такое ПЭП, откуда норма
  (ст. 5 ФЗ-63), что сервис не хранит документы вечно (ссылка на
  ретенцию — 7 дней, ADR-009), контакт для вопросов
- **Черновик, требует review юриста** — та же оговорка что уже в спеке
  §7, не выдавать за финальную юридическую консультацию. Не в скоупе
  E7 искать юриста — это отдельная задача владельца после MVP.

Один язык (русский) — норма ФЗ-63 и целевая аудитория контрагентов
русскоязычные, дублировать на английский не нужно (это не маркетинговая
страница, а юридическая справка к конкретному подписанию).

### 2.2 Ссылка в футере кабинета

Спека §7: «ссылка в футере кабинета» — сейчас есть только в футере
`sign/index.html` (E2). Проверить `app/index.html` (кабинет) — если в
футере такой ссылки нет, добавить тем же паттерном
(`<a href="/pep-agreement" target="_blank">Соглашение об ПЭП</a>`).

### 2.3 Тач-цель чекбокса — не однозначно, требует проверки на устройстве

`.consent-row input[type=checkbox]` — сам квадратик 20×20px, меньше 44px.
Но это `<label>`, оборачивающий и чекбокс, и многострочный текст — клик
по всей строке текста тоже переключает чекбокс, так что *эффективная*
кликабельная область скорее всего уже ≥44px по высоте за счёт текста.
Не переделывать превентивно — это пункт ручного теста §3, а не заведомый
баг. Если на реальном телефоне окажется что мимо текста не попадает —
тогда точечный фикс (`padding` на `.consent-row` или явный `min-height`).

## §3. Ручное QA — владелец, не кодер

Код готовит почву, но camera capture на iOS Safari и touch-рисование на
Android исторически полны сюрпризов, которые не ловятся статическим
анализом кода. Чек-лист (реальные iPhone Safari + Android Chrome, не
эмулятор):

- [ ] `/sign/{token}` открывается, PDF рендерится и скроллится
- [ ] Вкладка «Фото» — `capture="environment"` реально открывает камеру
  напрямую (не галерею) на iOS Safari
- [ ] Вкладка «Нарисовать» — canvas рисует пальцем без лагов/обрывов линии
- [ ] Чекбокс ПЭП — тап по тексту (не только по квадратику) переключает
  состояние (см. §2.3)
- [ ] Кнопка «Подписать» реально disabled пока не оба условия (чекбокс +
  обработанная подпись)
- [ ] После подписания — бейдж «✓ Договор подписан», кнопка «Скачать»
  реально скачивает файл на телефоне (не просто открывает в новой вкладке)
- [ ] `/pep-agreement` открывается, читаемо на маленьком экране
- [ ] Ссылка из футера кабинета на `/pep-agreement` открывается новой вкладкой
