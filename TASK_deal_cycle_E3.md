# TASK: SignfinderLand v2.0.0 Deal Cycle — Эпик E3 (Передача ссылки из кабинета)

## Контекст

E1 (backend: модель Deal, приватные API) и E2 (публичная страница
подписания) закрыты и подтверждены на test. E3 — самый лёгкий эпик
цикла (~1 день по спеке): **чисто фронтенд**, backend ничего не меняет.

Весь нужный API уже существует и задеплоен:
- `POST /v1/deals` — создание сделки (E1)
- `POST /v1/deals/{id}/mark-shared` — отметка что ссылка передана (E1)
- `GET /v1/deals` / `GET /v1/deals/{id}` — просмотр сделок (E1, пригодится в E4)

Deeplink-и на Telegram/WhatsApp формируются **на клиенте**, backend в
передаче не участвует вообще (см. спека §0 — принципиальное решение
всей версии, никаких рассылок).

**Про существующий stash.** В этом же репозитории может лежать
`git stash` с более ранней, несогласованной реализацией похожей логики
(`createDealAndRenderShare()`) — она была написана без TASK-файла, в
обход процесса (см. `GIT_WORKFLOW.md` §Journal 2026-07-25, Правило №5).
Можешь `git stash pop` и **свериться построчно с этим TASK-файлом**
как с референсом — но не подгонять задачу под старый код. Если что-то
там расходится со спекой ниже (например, другой набор кнопок, другой
момент вызова `mark-shared`, другой текст сообщения) — спека и этот
TASK-файл имеют приоритет, переделывай под них, а не наоборот.

## §2. Задача

### 2.1 Создание сделки — привязать к существующему флоу подписания

После того как `workSign()` успешно подписывает документ (существующий
флоу кабинета, не E2), автоматически создать `Deal`:

- `POST /v1/deals` с телом: `original_pdf_b64` (документ до подписи
  инициатора), `initiator_signed_pdf_b64` (результат `workSign()`),
  `saved_anchors` (полный список якорей из `_workAnalyzeResult`, не
  только сторона контрагента — фильтрация по `party_role` происходит на
  бэкенде при отдаче публичного view, см. `DEAL_CYCLE_SPEC.md` §6)
- Сохранить ответ (`deal_id`, `share_token`, `share_url`) в состояние
  (по аналогии с `_currentDeal`, если формат из stash-черновика подходит
  — используй, если нет, определи сам подходящую структуру)
- Если `POST /v1/deals` падает — не ломать основной флоу подписания:
  пользователь должен получить свой подписанный PDF в любом случае
  (существующее поведение), создание Deal — дополнительный шаг, его
  сбой не блокирует скачивание. Залогировать ошибку, тихо продолжить.

### 2.2 Блок «Передать контрагенту»

После успешного создания Deal — показать блок в том же месте где сейчас
кнопки «Скачать»/«Поделиться» (toolbar превью или под ним, смотри что
логичнее по существующей вёрстке). Три кнопки:

**📋 Скопировать ссылку**
```js
navigator.clipboard.writeText(shareUrl)
```
Показать короткое визуальное подтверждение (toast/смена текста кнопки на
«Скопировано ✓» на пару секунд) — по аналогии с существующими
`msg`-паттернами кабинета.

**✈️ Открыть в Telegram**
```js
const text = encodeURIComponent(`${initiatorName} направил вам договор на подпись через SignFinder. Откройте ссылку, ознакомьтесь и подпишите:`);
window.open(`https://t.me/share/url?url=${encodeURIComponent(shareUrl)}&text=${text}`, '_blank');
```
`initiatorName` — email пользователя если имя не заполнено в профиле
(есть в `pf-name`/профиле, посмотри как сейчас достаётся).

**📱 Открыть в WhatsApp**
```js
const text = encodeURIComponent(`${initiatorName} направил вам договор на подпись через SignFinder. Откройте ссылку, ознакомьтесь и подпишите: ${shareUrl}`);
window.open(`https://wa.me/?text=${text}`, '_blank');
```
(WhatsApp deeplink кладёт ссылку внутрь текста, не отдельным параметром
— в отличие от Telegram)

**По клику любой из трёх кнопок** (не только «успешно скопировал», а
сам факт клика) → `POST /v1/deals/{id}/mark-shared` с
`{"channel": "copy_link" | "telegram" | "whatsapp"}`. Не блокировать UI
на этом вызове — fire-and-forget с логированием ошибки в консоль при
неудаче.

### 2.3 Дизайн

Переиспользовать существующий дизайн-язык (`--c-accent`, `.btn`,
`.card`, `.icon-btn` и т.д.) — не изобретать новые стили. Три кнопки
могут быть в ряд (аналог `.preview-actions` из панели превью) или
блоком — смотри что лучше ложится в текущую вёрстку `work` таба.

### 2.4 Что явно НЕ входит в E3

- Раздел «Мои сделки» (список всех сделок, статусы, drill-down) — это
  **E4**, отдельный TASK
- Уведомления о `viewed`/`signed` — не будет никогда (ADR-010)
- Повторная генерация ссылки / отмена сделки — не в скоупе версии
- Изменения в `signfinder-api` — не требуются вообще в этом эпике

## §3. Definition of Done

- [ ] Reading gate пройден, подтверждение отправлено, владелец подтвердил
- [ ] После `workSign()` автоматически создаётся Deal через `POST /v1/deals`
- [ ] Сбой создания Deal не ломает существующий флоу скачивания подписанного PDF
- [ ] Блок «Передать контрагенту» с 3 кнопками появляется после успешного создания Deal
- [ ] Копирование ссылки работает, есть визуальное подтверждение
- [ ] Telegram/WhatsApp deeplink-и открываются с корректным текстом и ссылкой
- [ ] Клик по любой кнопке вызывает `POST /v1/deals/{id}/mark-shared` с верным `channel`
- [ ] Дизайн консистентен с существующим кабинетом
- [ ] Ручная проверка на test: подписать документ → увидеть блок передачи →
      нажать «Скопировать» → вставить ссылку в адресную строку → убедиться
      что открывается `/sign/{token}` (публичная страница из E2) и показывает
      именно этот документ
- [ ] `GET /v1/deals/{id}` после клика по кнопке подтверждает
      `status: "sent"`, `share_channel_used` соответствует нажатой кнопке
- [ ] CI зелёный (если применимо к фронтенду — синтаксис/линт), PR открыт,
      смёржен владельцем
- [ ] `deploy.yml` дошёл до конца на test — мониторишь сам (Правило №4)
- [ ] `version.txt` не бампан (это E7)
