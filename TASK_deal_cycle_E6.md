## Контекст

**Важное уточнение формулировки** — чтобы не было путаницы: опросник
**живёт в веб-кабинете** (форма, пункт меню, обычный UI-флоу). В Telegram
уходит только **готовый ответ пользователя** — одним сообщением в личный
чат владельца через Telegram Bot API. Никакого Telegram-бота с диалогом
для конечного пользователя нет и не будет — пользователь никогда не видит
Telegram, весь его опыт — форма в кабинете.

E6 — самый маленький эпик цикла (~0.5 дня). Есть и backend-часть (новый
эндпоинт `POST /v1/feedback` в `signfinder-api`), и фронтенд-часть (пункт
меню + форма в `app/index.html`).

## §2. Задача

### 2.1 Backend — `POST /v1/feedback`

Новый эндпоинт (за Firebase Auth — пользователь должен быть залогинен,
как и весь остальной кабинет):

```python
class FeedbackRequest(BaseModel):
    model_config = ConfigDict(extra='forbid')
    feature_request: str  # "За какую фичу вы готовы заплатить?"
    contact: Optional[str] = None  # опциональный контакт
```

Логика:
- Взять `tenant_id`/email пользователя из JWT (для контекста в сообщении —
  чтобы ты знал от кого фидбек, даже если контакт не указан)
- Отправить в Telegram через Bot API `sendMessage`:
  ```
  POST https://api.telegram.org/bot{TG_FEEDBACK_BOT_TOKEN}/sendMessage
  {"chat_id": TG_FEEDBACK_CHAT_ID, "text": "..."}
  ```
- Текст сообщения — включи email пользователя, текст фичи, контакт если есть
- Если Telegram API недоступен/упал — не роняй запрос пользователю с 500,
  залогируй ошибку, но верни 200 (фидбек не критичен, пользователь не
  должен видеть техническую ошибку из-за сбоя стороннего сервиса).
  **Но:** залогируй громко (ERROR-уровень), чтобы в Cloud Logging было
  видно если Telegram систематически недоступен — иначе фидбек будет
  тихо теряться и никто не заметит

### 2.2 Frontend — пункт меню + форма

- Новый пункт в меню/сайдбаре кабинета: «💬 Что улучшить?» (по образцу
  существующих пунктов навигации)
- Форма: одно текстовое поле «За какую фичу вы готовы заплатить?»
  (textarea, не input — ответ может быть длинным) + опциональное поле
  «Контакт» (email/телефон/telegram — как удобно пользователю)
- Кнопка «Отправить» → `POST /v1/feedback`
- После успешной отправки — заменить форму на сообщение «Спасибо,
  передано разработчику» (по аналогии с другими confirmation-паттернами
  в кабинете, например `.msg.info`)
- Если запрос упал (сетевая ошибка, не 200) — показать «Не получилось
  отправить, попробуйте позже» — не молчать

### 2.3 Секреты — создание, не тобой

По аналогии с E5: значения секретов через тебя не проходят.

**Что нужно сделать владельцу (не тебе):**
1. Создать Telegram-бота через @BotFather → `/newbot` → получить
   `HTTP API token`
2. Добавить как секрет: `gcloud secrets create tg-feedback-bot-token
   --data-file=-` (владелец делает сам, как с `api-key` в E5)
3. Написать `/start` этому боту от своего аккаунта → получить свой
   `chat_id` через `getUpdates` → добавить как секрет
   `tg-feedback-chat-id`
4. Подключить оба секрета к Cloud Run: `--update-secrets=TG_FEEDBACK_BOT_TOKEN=tg-feedback-bot-token:latest,TG_FEEDBACK_CHAT_ID=tg-feedback-chat-id:latest`

**Что делаешь ты:** код эндпоинта читает `os.environ.get("TG_FEEDBACK_BOT_TOKEN")`
и `TG_FEEDBACK_CHAT_ID` — как обычные env vars, тем же паттерном что
`API_KEY`/`DEEPSEEK_API_KEY` в `dependencies.py`. Если их нет в env —
эндпоинт должен вернуть внятную ошибку в логах (не падать необработанным
исключением), но это не блокирует тебя писать и тестировать код —
тестируй с моком Telegram API, реальные секреты появятся когда владелец
их заведёт.

**Важно — учти урок E5.** Когда будешь писать инструкцию владельцу
для подключения секретов к Cloud Run — дай точные команды, но не
предполагай что они сработают с первого раза бездумно. Если возможно,
сформулируй проверочный шаг (curl с тестовым фидбеком → проверка что
сообщение реально пришло в Telegram) как часть твоего DoD, а не
предположение.

## §5. Что НЕ делать

Всё из `GIT_WORKFLOW.md` §Явные запреты плюс:

  реальным значением — дай владельцу точную команду, пусть выполнит сам

  пользователь никогда не взаимодействует с Telegram напрямую
- Не бампай `version.txt` (веб-клиент) — это E7
