перед тем как считать эпик закрытым.

## §1. Задача

Reading gate не требуется — это прямое продолжение E2 в той же сессии,
контекст свежий.

### 1.1 Создать реальную сделку на test

Через приватный API (уже задеплоен и подтверждён в E1):
1. Получить валидный Firebase JWT для тестового аккаунта на
   `signfinder-cab-test` (как обычно получаешь токен для ручных проверок)
2. `POST /v1/deals` с реальным подписанным PDF (можно взять любой тестовый
   договор, например тот что уже используется в существующих ручных
   проверках проекта — `Lebedev.png`/аналогичный тестовый PDF, если
   есть готовый подписанный образец; либо прогнать `/v1/me/analyze` +
   `/v1/me/sign` сначала, если готового PDF под рукой нет)
3. Получить `share_token` из ответа

### 1.2 Пройти happy path в браузере

1. Открыть `https://signfinder-cab-test.web.app/sign/{share_token}`
   (реальный токен, не выдуманный)
2. Убедиться PDF viewer показывает документ (сторону инициатора)
3. Поставить чекбокс ПЭП
4. Пройти **хотя бы один** способ ввода подписи (файл — самый простой
   для проверки без реального телефона; если есть возможность
   протестировать камеру/canvas тоже — отметь отдельно, но файл
   обязателен как минимум)
5. Убедиться что превью обработанной подписи (после вызова
   `/v1/signers/{tmp}/signature/process`) реально показывается с
   confidence — не просто «не упало», а показывает разумное значение
6. Нажать «Подписать»
7. Убедиться что появился финальный экран, PDF в viewer теперь финальный
   (с юр. блоком если он уже реализован — см. §2.2 из основной задачи E2,
   если отложил текст блока до E7, здесь просто подтверди что PDF вообще
   сгенерировался и открывается)
8. Скачать финальный PDF — убедиться файл реально валиден (открывается
   в любом PDF-ридере, не просто «скачался нулевой файл»)

### 1.3 Проверить состояние Deal после подписания

Через приватный API `GET /v1/deals/{id}` (тем же JWT инициатора) —
убедиться:
- `status == "signed"`
- `audit_log` содержит событие `signed`
- Финальный PDF доступен через `GET /v1/deals/{id}/final-pdf`

### 1.4 Проверить повторную попытку подписания (409)

Открыть **тот же** `/sign/{share_token}` ещё раз после того как сделка
уже `signed`. Убедиться:
- Страница показывает что сделка уже подписана (не форму ввода заново)
- Если случайно вызвать `POST /sign` повторно напрямую (curl) — вернётся
  409, не перезапишет `final_pdf_path`

### 1.5 Сверить core version

Подтвердить: `signfinder-core` версия `1.21.0` — это состояние ДО начала
работы над E2 (унаследовано от более ранней задачи с reasoning-моделью),
или E2 сам внёс изменения в core? Если второе — объяснить какие именно
изменения и почему, поскольку `TASK_deal_cycle_E2.md` явно просил core
не трогать.
