## §1. Пустое состояние кабинета — раскладка по ширине

`app/index.html`, экран «Здесь появится предпросмотр документа».

### Проблема
Сейчас: справочник по иконкам тулбара идёт первым, длинной колонкой в одну
ширину, под ним — нумерованные шаги «что делать». Главное («как работать»)
спрятано под второстепенным («что означают значки»), экран тянется вниз при
пустой правой половине.

### Что нужно

**Шаги наверх, горизонтально — 4 карточки в ряд** (`grid-template-columns:
repeat(4, minmax(0,1fr))`), каждая: номер + иконка, заголовок в одно-два
слова, подпись в одну строку:

| № | Заголовок | Подпись |
|---|-----------|---------|
| 1 | Профиль | ФИО и образец подписи |
| 2 | Договор | Места подписи найдутся сами |
| 3 | Проверка | Добавьте или уберите подпись |
| 4 | Контрагенту | Он подпишет без регистрации |

Шаг 4 — новый, его в текущей инструкции нет вообще (Deal Cycle не описан).
Выделить акцентной подложкой (`--c-accent-bg`) — это то ради чего весь
релиз, остальные три нейтральные.

**Справочник иконок — ниже, в две колонки** (`repeat(2, minmax(0,1fr))`),
подписи сократить до одной строки каждая. Текущие формулировки читаются
один раз в жизни и дальше только занимают место. Шесть пунктов в две
колонки = втрое ниже, чем сейчас.

Формулировки: Запомнить шаблон / Применит расстановку к похожим ·
Добавить подпись / Кликните на место в документе · Убрать подпись /
Лишняя на текущей странице · Скачать / Готовый подписанный PDF ·
Передать контрагенту / Ссылка в Telegram, WhatsApp · Поделиться файлом /
Экспорт PDF в другое приложение.

**Внизу** одна строка: «Статус каждой отправленной сделки — в разделе
Мои сделки» — связать экран с разделом, куда пользователь пойдёт дальше.

Справочник иконок на пустом экране **оставляем** (не прятать до первой
загрузки) — на тач-устройствах hover не существует, там это единственный
способ узнать назначение кнопок.

## §2. Цветной hover на иконках тулбара

Сейчас иконки серые в любом состоянии. Оживить: при наведении — цвет по
смыслу действия + лёгкая подложка.

```css
.toolbar-icon { color: var(--c-muted); padding: 7px; border-radius: var(--radius);
                transition: color .15s, background .15s; cursor: pointer; }
.toolbar-icon:hover { background: var(--c-bg); }
```

| Иконка | Цвет hover | Почему |
|--------|-----------|--------|
| Запомнить шаблон | `#BA7517` янтарный | сохранение |
| Добавить подпись | `#378ADD` синий | редактирование |
| Убрать подпись | `#E24B4A` красный | **единственное разрушающее действие**, на мобильном по нему легко промахнуться — цвет здесь не украшение |
| Скачать | `#639922` зелёный | завершение |
| Передать контрагенту | `#7F77DD` фиолетовый | главное действие Deal Cycle |
| Поделиться файлом | `#5F5E5A` серый | нейтральный экспорт |

Добавить `title` (нативный тултип) на каждую иконку с текстом действия —
дешевле кастомного тултипа и работает с клавиатуры.

`:hover` не срабатывает на тач-устройствах — это ожидаемо и покрыто тем,
что справочник в §1 остаётся на экране.

## §3. Опросник «Что улучшить?» — три правки по итогам просмотра

`signfinder-api/app/routers/feedback.py` + форма в `app/index.html`.

### 3.1 Убрать поле «Контакт» целиком

Форма живёт за Firebase Auth — пользователь уже залогинен, email уже
известен и **уже подставляется в сообщение** (`_format_message`, строка
`От: {email}`). Спрашивать контакт повторно — просить у человека то, что
у нас и так есть.

- Убрать `contact` из `FeedbackRequest`
- Убрать строку `Контакт: {contact}` из `_format_message` и переменную
  `contact` в нём
- Убрать поле из формы во фронте

Строка `От: {email}` остаётся — она и есть контакт для связи.

### 3.2 Убрать `TWO_SIDED_SIGNING` из `PremiumFeature`

«Двустороннее подписание через сервис» — это ровно то, что уже сделано
в E1-E7 и работает на test. Спрашивать «готовы ли платить» за
существующую функциональность бессмысленно и выглядит так, будто мы не
знаем собственный продукт.

Убрать из enum `PremiumFeature`, из `_PREMIUM_FEATURE_LABEL`, из формы.

### 3.3 Заменить `TEAM_ACCESS` на интеграцию с почтой

Было: `TEAM_ACCESS` / «Командный доступ — несколько сотрудников на аккаунт».
Стало:

```python
MAILBOX_INTEGRATION = "mailbox_integration"
```

Лейбл: **«Интеграция с почтовым ящиком и обработка в фоновом режиме»**

Это уже описанный в концепции IMAP-агент (`SignFinder_Concept_v2_0.md`
§12.3, v1.16) — договоры прилетают на почту, разбираются и подписываются
без участия человека. Проверяем спрос до реализации, а не после.

Заменить ключ в enum, в `_PREMIUM_FEATURE_LABEL`, в форме.

### 3.4 Переформулировать вопрос про рекомендацию

Было: «Порекомендовали бы коллеге?» → стало: **«Вы уже порекомендовали
коллеге?»**

Это не косметика формулировки, а смена смысла: вместо гипотетического
намерения спрашиваем свершившийся факт. Соответственно переименовать
поле, чтобы код не врал о том что хранит:

- `would_refer: Optional[bool]` → `has_referred: Optional[bool]`
- Строка в Telegram-сообщении: `Порекомендовал бы коллеге:` →
  `Уже порекомендовал коллеге:`
- Значения `да`/`нет`/`не отвечено` — без изменений

Мигрировать нечего — поле нигде не хранится, только уходит в Telegram.

### Итоговый состав опросника после правок

1. `usage_type` — радио, 4 варианта (без изменений)
2. `premium_features` — чекбоксы, **4 варианта**: локальная установка ·
   расширенные лимиты · API/интеграции · интеграция с почтовым ящиком и
   обработка в фоновом режиме · + текстовое «Другое»
   (`premium_features_other`)
3. `has_referred` — да/нет тоггл, «Вы уже порекомендовали коллеге?»

Ничего не обязательно, кнопка «Отправить» активна если заполнено хотя бы
одно поле.
