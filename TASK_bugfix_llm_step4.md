# TASK: Bugfix — Шаг 4 «LLM не вернул паттерны» на test (после смены модели)

## Контекст

Продолжение диагностики из `TASK_bugfix_llm_step3.md`. Модель/провайдер
LLM сменили — прошли дальше, шаг 3 (LLM-извлечение нашей стороны) теперь
отрабатывает. Новая точка отказа — **шаг 4: генерация regex-паттернов
для поиска мест подписи** возвращает пусто/невалидно, кабинет показывает
«LLM не вернул паттерны».

По пайплайну (`SignFinder_Concept_v2.0.md` §5.1) это соответствует шагу
«3 — Генерация regex под этот документ»
(`signfinder/prompts/regex_generation.py`) в терминах core; в терминах UI
кабинета — «Шаг 4».

**Рабочая гипотеза** (не факт, проверить): промпты в проекте осознанно
**универсальные** — один текст на все 4 провайдера, различия изолированы
в JSON-механике (`complete_structured()`, см. концепция §5.2, §8.3). Смена
модели/провайдера могла обнажить слабость именно в JSON-механике для этого
конкретного провайдера на этом конкретном шаге — либо модель слабее
справляется с генерацией регулярок, либо парсер структурированного вывода
для неё работает не так как для DeepSeek.

**Не трогать `signfinder-core` без разбора** — регулярки и JSON-парсинг
внутри пакета, изменения там требуют версионирования по `DEPLOY_CONSTRAINTS.md`.
